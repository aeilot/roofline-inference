# Qwen3-0.6B 在 MacBook Air M4 上的推理资源参考线与实验结果

2026-10-07 修订 · Louis Deng

## 摘要

本项目用模型计算图与硬件微基准建立资源参考线，并比较现有推理引擎。当前证据支持：在本机、本模型与所测工作负载下，decode 的表现与带宽限制的解释一致；短 prompt 的实现优化有明显收益。参考线不是已经证明的硬件绝对极限，不能据此断言只剩 1–4% 的优化空间。

- 默认 prefill 图删除不影响最后一个 token 和 KV 输出的最终层计算。修订参考时间：decode 上下文 512 / 4k / 32k 为 **12.0 / 16.0 / 48.0 ms**；prefill 长度 512 / 4k / 32k 为 **0.127 / 1.454 / 39.870 s**。
- v3 simple 的配对几何平均比：TTFT 16 / 64 / 256 为 **1.682 / 1.591 / 1.250**；decode 512 / 4k 为 **1.073 / 1.067**。这些比值来自现有数据，不是新实验。
- 32k TTFT 比值为 **0.993 [0.855, 1.162]**，decode 为 **1.001 [0.943, 1.068]**。区间为描述性 bootstrap 区间；长上下文收益仍未确定。
- KV 策略表测量的是近似输出变化，时间来自理想资源模型。尚未实测支持“几乎无质量损失就能达到 31 ms”等性能承诺。

## 计算范围与参考线

A 级实现允许融合、改变求和顺序、重算和删除无用计算，但必须计算**所选有用图**中每个收缩乘积项。输出约定为每个 prompt 的最后一个 token 与所有层完整 BF16 KV；不要求输出所有位置的 logits。最后一层只有最后一个 query、attention 输出、O 投影与 MLP 行需要保留；K/V 仍需生成全部位置。

`workload.prefill` 与 `prefill_graph` 默认使用该图。`prune_final=False` 保留历史完整乘积图，仅供旧数据口径核对。v2 会多计算部分最终层 Q，属于允许的额外工作。删除无用行不应归因于单纯的 kernel 效率改进。

给定图、存储表示及硬件速率上限，标准资源论证为：

```
T >= max(W / P, Q_b / B_b)
```

这里 W 是必须执行的收缩工作，Q_b 是在指定存储假设下的流量下界。要将数值称为严格时间下界，还必须证明 P、B_b 是所有允许实现的吞吐上限，并证明容量估计不低于真实容量。

本项目的 3.68 TFLOP/s、102.7 GB/s 是微基准最快观察值，不能提供这种证明。当前输出标为 `calibrated_resource_reference`，同时返回 `hardware_ceiling_certified=false`。max 形式是必要资源约束，不能单独证明存在达到它的调度。

DRAM 参考线默认扣除模型中所有片上存储可能驻留的输入，总计 17 MiB；不扣除必须写出的 KV 与 token。`initial_resident_bytes=0` 表示冷启动。这是假定容量下的保守输入抵扣，不是实际缓存命中率测量。

KV 必读必写的论证条件是**明确存储 KV 的表示**。缓存 hidden、混合表示、压缩／重算状态的搜索尚不完备，不能把有限候选计划的比较称为所有数学等价实现的排除证明。exp 项使用标准 softmax 的计数；任意数学等价实现的特殊函数需求未另行证明。

[修订前后时间及速率敏感性数据](../results/figures/review_corrections.json)由 `scripts/review_correction_report.py` 重算，没有新增计时。以 120 GB/s 假设替代 102.7 GB/s，会使带宽参考时间约再下降 14.4%，说明接近校准线不等于接近绝对极限。

## 理论推导的证据等级

- 收缩计数和条件性的资源 max 形式可直接检查。
- 独立 GEMM 与 attention 的 I/O 界依赖其定理及本项目推广的假设；整图算子合成仍需独立审查。
- 6.12 的融合与重算推导是**实验性候选界**。默认结果只应用必读必写项，候选值单独返回为 `experimental_pebble`；Python API 可用 `include_experimental_fused=True` 探索。
- 该推导需要补齐有用乘积到跨段部分和的映射、进入／离开段预算、任意求和与 split-K、私有链重算二分及多核合并的论证。单调性、与暴力搜索吻合、低于某个可行方案，都不能代替证明。
- 算子边界界也是下界，不能作为真实最小流量的上界。要建立夹逼，必须计算具体可行调度的流量。

重新生成的容量与 roofline 图展示模型的资源约束。I/O 项低于计算项，只表示该 I/O 界没有进一步抬高参考时间，不能证明实际实现已受算力限制。

## 实验结果与统计修订

v3 simple：220 次有效计时、无排除；两个时段背靠背运行，只检验短时漂移。代码与语料有冻结哈希；dirty 标记的解释见 [NOTE.md](../agent-test/v3/results-simple/NOTE.md)。

[原报告](../agent-test/v3/results-simple/report.md)与原始记录保留。[修订分析](../agent-test/v3/results-simple/report-corrected.md)明确标注为**采集后修订**，不是原预注册检验。原分析脚本保存为 `analyze_preregistered.py`。

修订分析保留几何平均比与按时段重采样的描述性区间，移除把 bootstrap 尾部比例当作 p 值的做法。另用单侧精确符号检验，检验**配对比值中位数是否超过 1.02**，按固定场景族做 Holm 校正。这与原来的几何平均假设不同。

在时段内配对独立、零假设下超过阈值的概率不大于 1/2 的条件下，TTFT 16 / 64 / 256 和 request 256×256 通过修订检验；其余场景未定。decode 512 / 4k 的观察收益仍为约 7%，但小样本在该检验与校正下不足以下肯定判定。“未定”不表示不存在收益。

bootstrap 小样本覆盖率未验证；热状态序列相关可能破坏配对独立假设。配对区间不能描述跨日、跨设备波动。区间落在 [0.98, 1.02] 内不宣称统计等价，区间半宽不称为最小可检出效应。

数值 gate 是针对所测位置的经验筛查。“未检出误差更大”不等于证明质量非劣；长上下文未被短上下文 gate 充分覆盖，FP32 也不是实数精确 oracle。

## 消融与热状态

旧消融按 matmul → attention → 完整 forward → generate 相减。各差值在固定顺序下可相加，但它们是**边际效应**，不是部件的独立损失：增删算子会改变缓存、融合、寄存器压力、并发与 CPU/GPU 重叠。旧消融使用完整乘积图，其图表已明确标注历史口径。

删除 exp 没有加速、删除 softmax 反而更慢，支持“所测试变体没有获益”，不能唯一证明损失来自数据路径或排除 softmax 的成本。纯 MMA 与 attention 的持续吞吐差异，与热及搬运解释一致，因果归因仍待 trace 和受控对照。

同一 32k prefill 在旧测量中为 55.8 s 与 70.7 s，说明系统状态影响很大；不能仅凭先后两次测量把差异完全归因于热降频。`thermalState=0` 和允许探针变慢 10% 的门控，也不足以支持百分之几的极限判断。后续需要独立日期、稳定持续负载、频率／功耗或更敏感探针的记录。

## KV 质量实验

6.14 的实测量为 KL、top-1 一致率与 teacher-forced NLL 变化。质量代码仍先计算完整前缀分数再 mask，并先反量化回 BF16；它不是低位宽或稀疏 decode 的性能实现。

32k 时四个 prompt 内容约 89% 重叠，1024 个 token 位置不能视为 1024 个独立样本。没有置信区间及预定义任务质量容忍阈值；续写 KV 保持精确，未测长期自由生成与下游任务。BF16–FP32 差异只作数值参照，不能定义“免费”。

目前可以说：在这份语料上，8 bit 的观察分布变化较小；KIVI 风格 3/4 bit 与 Quest 风格选择值得继续测；固定预算策略出现较大的尾部 KL。不能断言“只有 8 bit 免费”“2 bit 普遍不可用”，或按未经实测的时间作质量—速度排序。Quest 按 query head 选页、时间模型按 KV head 计流量的差异仍未消除。

流式 attention 的最坏情况定理限制的是一般输入保证，不是 Qwen3 实际分布的排他性结论。当前样本的 k-center 半径仅表明所检查的 SubGen 保证不实用，不能证明模型完全不可聚类或不存在其他结构性算法。text/random 相似也不能代替 RoPE 与归一化的因果消融。

## 下一步

1. 在独立日期按新方案采集足够的配对，覆盖稳定持续负载与长上下文数值检查。
2. 实测真实量化 KV decode，验证理想流量模型预测；以互不重叠文档与任务指标评估质量。
3. 对实验性融合界进行独立证明审查，并用完整可行调度建立流量上界。
4. 用 E1 与受控消融区分调度、无用计算删除和 kernel 收益。
5. 另做“只用剖析”与“剖析加资源参考线”的导航对照。当前实验没有证明导航仪的增量价值。
